我给自己搭了个一次性邮箱：不用注册、免费、10 分钟自动销毁

先说个场景，你肯定遇到过。

某个网站要你留邮箱才能看内容，某个 App 要邮箱验证才能试用，某个论坛注册要收验证码。你留了自己的常用邮箱，然后接下来三个月，垃圾邮件没停过。

我一开始的办法是忍着。后来用网上的临时邮箱网站，能用，但问题不少。一是很多是公共收件箱，你的验证码理论上别人也能刷到；二是这类热门域名被成千上万人用过，不少网站直接把它拉黑了，你填了地址对方根本不给发信。所以我干脆自己搭了一个。

用的是自己的域名，不会被拉黑。地址只有我知道，没人能看。

整个过程跑在 Cloudflare 免费额度上，没花一分钱，也没租服务器。

方法我完整写下来。你只要有 Cloudflare 账号、一个域名，加上会用 AI 帮你写代码，半小时能搞定。

01｜先看效果

打开我的地址，一个输入框让你填邮箱前缀。填 test、abc、vip，随便什么都行——不需要注册，也不存在"这个用户名被占用"这回事。

选好前缀和域名，它把完整地址给你：test@你的域名。

拿着这个地址去任何网站注册。验证码邮件到了，页面上刷新一下，验证码已经自动提取出来了，绿色框里，一键复制。

用完关掉。10 分钟后邮件自动销毁。

还能多开：a@你的域名、b@你的域名、c@你的域名 同时收，互不干扰。

有个细节我比较喜欢，页面每 15 秒自己刷一次。所以不用一直盯着点，验证码到了自己就冒出来。

02｜现成的临时邮箱网站，绕不开三个问题

我都试过。

隐私。 大部分免费临时邮箱是公共收件箱，谁都能刷。有些更离谱——不设密码，谁先访问谁就是主人，你填的地址别人正好也在用，邮件混在一起。

拉黑。 那些热门域名被用了太多次，网站一看是临时邮箱域名，直接不发信。

时长。 很多网站限制你只能收 10 分钟、20 分钟。填个注册表单磨蹭一会儿，过期了。

用自己的域名，这三个问题一起消失。域名就你在用，不会被拉黑；页面有密码，只有你能进；存活时间自己定。

03｜技术上是怎么回事

说白了三件事。

让发到「你的域名」的邮件，转给一段程序处理。

Cloudflare 有个免费功能叫 Email Routing，本来是把你域名的邮件转发到某个真实邮箱。但它也支持转发给 Worker——Worker 就是 Cloudflare 上跑的一小段代码，免费额度每天 10 万次请求。

链路就成了：别人发信给 test@你的域名 → Cloudflare 收到 → 交给我的 Worker → 存起来。

存哪？存 KV。

KV 是 Cloudflare 的键值存储，也免费。我分了 两层：索引层放"这个邮箱收到了哪些邮件"的摘要，正文层放每封邮件的完整内容。列邮件时只读一个 key，快，也省额度。

同一段 Worker 顺便当网站服务器。

Worker 不只处理邮件，还能响应网页请求。所以收信和网页界面，一个 Worker 全包了，不用再部署一个网站。

三件事一段代码干完。这就是为什么成本是 0——没有服务器，全是免费额度。

04｜验证码怎么自动抓出来

这个功能看着简单，我踩了两轮。

第一轮，直接从邮件源码里搜数字。

抓出来一堆乱七八糟的东西。邮件源码里除了正文，还有 MIME 头信息、服务商签名、退订链接。我在一封测试邮件里搜出来的"验证码"是 are-ema——那是 Coremail 这个词被规则切错了。

第二轮，中文主题显示成乱码。

邮件主题带中文的话，源码里长这样：

Subject: =?utf-8?B?44CQ6aqM6K+B56CB44CR...

这是 MIME 编码。直接显示，用户看到的就是这串东西，压根不知道邮件说啥。

正确做法是先解码，再匹配。

用 postal-mime 这个库把原始邮件解开，主题还原成「【验证码】您的验证码是 482139」，正文还原成正常文本。然后在这份干净内容里去找验证码。

匹配规则分了几层优先级：先找中文「验证码」后面跟的 4-8 位字符，这个最准；再找英文 code、verification code；最后才用"孤立的 6 位数字"兜底。

改完再测，同一个主题从乱码变成了「【验证码】您的验证码是 482139」，验证码从错的变成了对的。这种问题你不真发一封信测，根本发现不了。

05｜一个隐蔽的坑：部署会清空绑定

Worker 要读 KV，得先"绑定"——配置里声明"这个 Worker 能用这个 KV"。用官方工具 wrangler 部署，配置写在文件里，一般没事。

但我当时是直接调 Cloudflare 的 REST API 部署的。第一次部署完，网页能开，所有读邮件的接口全 500，错误码 1101。

排查半天，原因是：手动调 API 时，metadata 里没带 bindings 字段，Cloudflare 会把原有绑定清空。 代码没变，KV 也没变，就是那根线被拔了。

修法是在部署的 metadata 里把绑定带上：

{
  "main_module": "worker.mjs",
  "bindings": [
    { "type": "kv_namespace", "name": "MAIL_KV", "namespace_id": "你的KV-id" }
  ]
}

用 wrangler 的读者基本遇不到。但你要是也手搓 API，记着这条。

06｜安全上做了几件事

页面挂在公网，有几个地方必须处理。

登录。 页面不是打开就能用，要先过账号密码。会话用签名 Cookie——服务器拿密钥加过期时间算个签名，下次请求带签名来验，而不是明文存密码。有效期 7 天。

收件白名单。 这是我最推荐加的一条。规则很硬：只有发到我的域名的邮件才处理，其他一律丢掉。

为什么重要？KV 每天写入额度是 1000 次。如果有人拿你的域名当靶子狂轰垃圾邮件，额度很快见底，你正常该收的验证码反而收不到了。加了白名单，垃圾邮件在写 KV 之前就被拦掉，零消耗。被丢的邮件会记一条日志，谁发的、发到哪，方便以后查。

密码别太短。 页面公网可访问，密码就是唯一的门。我用的是随机密码。真担心暴力破解，可以再加"连续错 5 次锁 10 分钟"。

07｜你需要准备什么

Cloudflare 账号，免费版够。一个域名，必须托管在 Cloudflare（NS 记录切过去）。Node.js 用来打包代码，v18 以上。加上会用 AI 工具——不会写代码也行，把需求说清楚让它写。

域名是唯一有门槛的。还没买的话去任何注册商买一个，最便宜一年几十块，然后把 NS 记录改到 Cloudflare。

没有域名行不行？ 不行。Cloudflare 的收信必须绑自己的域名——这也是它比公共临时邮箱强的地方。

08｜部署五步

完整代码和说明我整理好了，照着做。

开 Email Routing。 Cloudflare 后台选中域名 → 左侧 Email → Email Routing → 点 Enable。它让你加 MX 和 TXT 记录，点自动添加就行，不用手填。

建 KV。 命令行一句：

npx wrangler kv namespace create MAIL_KV

它给你一个 id，记下来。

改配置、部署。 打开代码文件，改开头几行：

const CONFIG = {
  ALLOWED_RECIPIENTS: ['@your-domain.com'],   // 收件白名单
  DOMAINS: ['your-domain.com'],                // 网页可选域名
  WEB_USERNAME: 'admin',                        // 登录账号
  WEB_PASSWORD: '换成你的强密码',                // 登录密码
  MAIL_TTL: 600,                                // 邮件存活 600 秒 = 10 分钟
};

然后：

npx wrangler deploy

绑域名 + 配收信路由。 这步有两小步，第二小步最容易漏。先把 Worker 挂到网页地址（比如 mail.你的域名）；然后回 Email Routing → Routing rules → Catch-all address → Edit → Action 选「Send to a Worker」→ 选中你的 Worker → 保存。

只做前一小步、漏了后面，网页能开，但一封邮件都收不到。卡在这儿的人不少。

验证。 登录先试通：

curl -i -X POST https://mail.你的域名/__auth \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"你的密码"}'

拿到 Cookie 后，随便发一封信到 test@你的域名，再查：

curl -H "Cookie: tm_session=上面的token" \
  https://mail.你的域名/api/check/test

接口路径是 /api/check/前缀，不是完整邮箱地址——我写过一版错的，返回 invalid path，白折腾一会儿。

09｜费用

Workers 每天 10 万次请求，KV 每天读 10 万次、写 1000 次。个人用连零头都占不到，0 元。

花钱的只有域名，一年几十块，而它你还能干别的用。
